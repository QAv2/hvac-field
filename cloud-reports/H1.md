## Summary

All five areas are done. Every check is green. Four new repeatable checks are in `tools/`:
- `offline_check.mjs`
- `fuzz.mjs`
- `a11y_check.mjs`
- `physics_check.mjs`

The engine edge cases are in `tests/scenarios/engine.yaml`.

Real bugs found and fixed:

1. **An update could ship a mixed-version cache.** The service worker filled the new cache through the browser's
   HTTP cache. GitHub Pages lets files sit there for 10 minutes, so the new cache could hold the old `kb.json`.
   A connection drop during the update also went unnoticed, because the stale copy "succeeded".
2. **Readings typed in other units were misread, and the misreading became findings.**
   - "8,1 bar" in the suction box was read as 8.1 psig and became "evaporator very cold, superheat high".
   - "4°C" was read as 4 °F.
   - "24,000" Btu/h was read as 24.
3. **Impossible reading pairs still became findings.** A superheat of −80 °F became "low superheat". The
   wet-bulb-above-dry-bulb and similar checks warned, but the readings still fed the diagnosis.
4. **The mixed-air energy-balance check never ran.** It read input IDs that don't exist.
5. **Glycol freeze points claimed up to 4 °F more protection than the published tables** for ethylene glycol at
   40–55 %.
6. **The iPhone number pad has no minus key.** −20 °F could not be typed in any reading or calculator box.
7. **Smaller bugs:**
   - the PT table could loop forever;
   - psychrometric functions clamped RH over 100 % instead of refusing it;
   - the flue-efficiency calculator gave efficiencies over 100 % for a stack cooler than the room;
   - contrast failed in both themes;
   - several tap targets were under 44 px;
   - a lead that doesn't explain the findings was still labelled "Strong lead";
   - enough skipped checks could empty the next-check card while useful checks remained.

## 1. Offline guarantee

**Audit of `docs/sw.js`, its cache list and the stamp:**

- **The cache list is complete.** `build.py` lists every file under `docs/` except `sw.js` and the standalone
  file. The headless run requests 17 files during a full session: home, search, diagnosis, an answer, readings, a
  cause, all nine calculators, about, and the manifest and icons. All 17 are in the list.
- **The stamp really forces an update.** The stamp is a SHA-256 over every cached file. Change any file and
  `sw.js` changes byte for byte, so the browser installs the new worker on the next online launch.
  `offline_check.mjs` builds three versions with `build.py --stamp` and checks that each gets a new stamp and
  replaces the cache.
- **Bug (fixed): the install read through the HTTP cache.** `addAll(ASSETS)` went through the HTTP cache, and
  GitHub Pages sends `Cache-Control: max-age=600`.
  - The test serves with that header. After an update, the new `fdx-<v2>` cache held v1's `kb.json`, and the
    relaunched app ran the old knowledge base.
  - A connection dropped mid-update was hidden too: the stale copy came from the HTTP cache, so a broken v3
    "installed".
  - Fix: fetch with `cache: 'reload'`.
- **Half-finished updates leave the old version working.** `addAll` is all or nothing. If it fails, the install
  fails and the old worker and its cache stay. The worker now also deletes the half-built cache on failure.
  The test covers a 500 on `kb.json` and a dropped connection. In both, the old cache stays complete and an
  offline launch still diagnoses. Once the server is fixed, the next launch completes the update.
- **Fallback (fixed).** An uncached request that failed offline got `index.html` back whatever it asked for, so
  a script or JSON request received HTML. Now only page navigations get the app shell.

## 2. Input robustness

`tools/fuzz.mjs` covers:
- the reading parser;
- every input of every system with garbage values;
- every calculator function with NaN, ±Infinity, huge and negative values, null and strings;
- each calculator screen with 300 random forms;
- search with empty text, emoji, markup, full-width and accented letters, NUL, mixed-case slang and long pastes;
- 600 random engine rounds with odd findings.

It is seeded: `--seed`, `--rounds`.

**Bugs it found, now fixed (each has a regression case in `fuzz.mjs`):**

| Input | Before | Now |
|---|---|---|
| `8,1 bar` in suction psig | 8.1 psig → evap sat −44 °F → superheat high, evap low | 117.5 psig ("read as 117.5 psig") |
| `815 kPa`, `0.81 MPa`, `132.7 psia`, `5 in. Hg` in a psig box | 815 psig / unreadable | converted to psig |
| `24,000` Btu/h (flow calculator), `1,234.5` | 24, 1.234 | 24000, 1234.5 (`4,5` is still 4.5) |
| `24k`, `2 tons`, `60 MBH` Btu/h | 24 / 2 / 60 | 24000 / 24000 / 60000 |
| `4°C`, `40C` in a °F box | 4 °F, 40 °F | refused, with a note: "this box is °F, not °C (4 °C = 39.2 °F; a 4 °C difference = 7.2 °F)" |
| `−40` (typographic minus), `– 40 °F` | silently dropped | −40 |
| `118.4.2`, `1e9`, `40 V` in psig, `😀` | 118.4 / dropped silently | refused, with a note under the box |
| −500 °F, 150 % RH, −20 psig, −12 A, smoke number 10 | used | refused as outside what the reading can be |
| Garbage in a box that has a default (e.g. rated static) | fell back to the default silently | left out, with a warning |
| Suction line −40 °F at 118 psig R-410A | warned, but "superheat low (−80 °F)" still fed the diagnosis | warned and left out until the readings agree |
| Wet bulb 80 / dry bulb 75 | warned, still used | warned and left out |
| Mixed air outside the outdoor/return pair | never checked (read `ahu.oa_f/ra_f/ma_f`, which don't exist) | reads `ahu.oat_f/rat_f/mat_f`; warns, and the readings still count, because this can be a real fault |
| Liquid 1234.5 psig on R-410A (past critical) | nothing computed, no word why | warning: outside the PT table |
| `rhFromWb(80, 85)`, `dewpoint(80, 150)`, `wetbulb(80, 150)` | RH > 100 % / clamped answers | null |
| `combustion` with stack 60 °F < air 70 °F, or O2 = 21 % | efficiency over 100 % / Infinity | null; the calculator says why |
| `capUnderLoad(−5, 370)`, `foTargetSh(NaN, 95)`, `glycolFreeze(NaN)`, `patmFromElev(NaN)` | negative µF / NaN | null / null / null / sea level |
| `gpm(24000, −10)` (ΔT typed the other way round) | −4.8 GPM | 4.8 GPM |
| PT calculator with a custom fit giving ~1e300 °F | **infinite loop** (`t++` is a no-op at 1e300) | table skipped |
| Combustion calculator after the guard above | crashed on `null.eff` (my regression, caught by the fuzz) | warning box |

Design choices:
- **°C in a °F box is refused, not converted.** Several °F boxes hold a difference (design ΔT, fan heat rise,
  subcooling target), and a difference converts without the +32. The note gives both conversions.
- **Pressure units do convert.** Gauge kPa or bar to psig is the same for a reading and for a difference.

Search was already robust: no throws, no findings from garbage, and mixed case reads the same as lower case.

**For a human:**

- **R-404A publishers spread about ±2 psi at 40 °F** (84.4 to 88.5 psig). Our table matches Arkema exactly.

- every check answered abnormal at once;
- every check answered normal;

- each source answer of a `follows` feature.

## Needs a human decision

1. **Branch name.** This work is on `claude/gifted-davinci-0p5ujk`, not `cloud/h1-harden`.
2. **Glycol source.** The switch from CoolProp to Dow and the two hydronic scenarios moved from 54 % to 56 % EG
   (section 3).
3. **°C in °F boxes is refused, not converted.** Converting would need each KB input marked as a temperature or a
   difference, for example a new `kind: delta` on inputs. That's a KB-schema change I left to you.
4. **The ± key** (and whether `inputmode="decimal"` should stay at all). Please try it on an iPhone.
5. **Wording.** "Leads, but doesn't explain everything" and the new helper line.
6. **Spurious updates.** `kb.json` carries a build timestamp (`meta.built`, shown on About). So every build
   changes the stamp and phones download a "new" version even when nothing changed. Making `built` come from the
   sources (e.g. their hash, or the last commit date) would stop that.
7. **Glove-size targets** (~56 px) for the chips and top-bar buttons (section 4).
